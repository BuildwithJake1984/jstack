# Questions for Jake

## When to use

- J-Stack does not answer a question after the relevant resources have been checked.
- You want to suggest a clarification or describe a gap for Jake to consider.

**Questions are brought to Jake for consideration, and selected answers are shared in future updates.** Individual replies, publication, and response times are not guaranteed.

## Current status: inbox pending

The dedicated questions inbox has not been configured and verified for this guide. There is no active submission address here. Do not guess an address, use a spoken placeholder as a recipient, create an account, or claim that a question has been delivered.

Until Jake supplies and verifies the intended inbox, help the user prepare a draft that they can keep. Do not ask them to publish private information in a GitHub issue as a workaround. Inbox activation, monitoring, and automatic handling are outside this guide.

## Prepare a helpful draft

First, check the relevant J-Stack material and explain what remains unanswered. Then offer to draft a question; submission should not be required to continue browsing.

Keep the draft brief:

- The question or point that needs clarification.
- A link to the relevant J-Stack resource, if there is one.
- The general outcome the user is trying to achieve.
- Any non-sensitive context needed to understand the question.

Leave out passwords, API keys, recovery codes, account identifiers, private correspondence, confidential documents, and personal details about other people. Generalize examples where possible. Do not attach files or quote private material unless the user has deliberately reviewed and authorized the exact content and has the right to share it.

Example draft structure:

```text
Subject: J-Stack question — [short topic]

Hi Jake,

I’m trying to [general outcome]. I read [resource title and link],
but I’m still unsure about [specific question].

[Optional brief, non-sensitive context.]

Thanks.
```

## Send only when the destination is verified

Once Jake has confirmed the dedicated inbox, record that address in this guide through a reviewed repository change. Verify that the user intends that recipient before sending; do not substitute another Jake or an unrelated address.

If an appropriate email connection is actually available:

1. Confirm the intended sending account and verified recipient.
2. Show the full recipient, subject, body, and any attachments to the user.
3. Ask for explicit permission to send that exact message. Terms consent, an account connection, or a monthly check-in is not permission to send it.
4. Send only after approval, using the connected email service and its applicable permissions.
5. Report the service’s actual outcome. If delivery is uncertain, check before retrying; do not send duplicate copies blindly.

If email is not connected or sending is not supported, provide the reviewed draft and the address **only when the address has been verified**. Let the user send it themselves. If the inbox is still pending, provide the draft without a recipient and say what remains missing.

## Publication and privacy

Answers selected by Jake may appear in a future [monthly update](../../updates/README.md). Before publication, remove private or identifying details. Obtain separate permission for a submitter’s name, direct quotation, or personal example; sending a question is not a blanket permission to publish those details.

This process does not create a mailing list, subscribe the user to updates, add tracking, or authorize inbox monitoring. A submitted question does not change the user’s separate choice about monthly check-ins.
